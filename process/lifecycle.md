# Жизненный цикл PDLC → SDD → результат

Предлагаемый процесс, требующий принятия владельцами продукта и разработки.

| Состояние | Что должно существовать для перехода | Кто отвечает за решение |
|---|---|---|
| Intake | Источник, конкретная проблема/возможность, связь с продуктовым результатом | Product |
| Needs analysis | Job, текущая альтернатива, baseline или его отсутствие, риски | Product + Research |
| Discovery | Проверяемая гипотеза, эксперимент и заранее заданные критерии | Research + владелец процесса |
| Shaping | Решение по направлению, scope/non-goals, UX, acceptance criteria, зависимости | Product + Design + Engineering |
| Ready for SDD | Все пункты ниже; ссылки на согласования | Product + Tech lead + QA; Security по типу данных |
| In SDD | Принятый версионный пакет и обратная ссылка на спецификацию разработки | Tech lead |
| Delivered | Результат QA, релиз/версия, наблюдаемость и rollback | Engineering + QA |
| Validated / Iterate / Stop | Измеренный эффект на когорте; решение о продолжении | Product + владелец процесса |

## Definition of Ready

- Проблема, пользователь, текущая альтернатива и evidence связаны с источниками.
- Решение по выбранному сценарию и приоритету записано; scope и non-goals однозначны.
- Сценарии успеха, ошибки и границы доступа выражены проверяемыми критериями.
- Согласованы профиль данных/нагрузки, UX и открытые параметры; блокирующих вопросов нет.
- Есть входные fixtures/эталоны и план проверки QA.
- Зависимости, оценка и доступная команда подтверждены; указан конкретный владелец.
- Определены метрики, rollout/rollback и правила приёмки.
- Получены ссылки на согласования Product, Engineering и QA; Security — если влияет на данные/действия.
- Приложены SDD URL и документ соответствия его шаблону. Поле «неизвестно» не считается закрытием.

Факт нахождения документа в `specs/` означает только проработку. Машинная проверка проверяет полноту реестра, но не заменяет содержательное ревью.

## Изменения после передачи

Новый источник или изменение критерия → новая ревизия постановки → change record с влиянием на тесты, оценку и сроки → согласование с владельцем SDD. Уже переданный пакет не редактируется незаметно. Если необходимость исчезла, задача получает stop/superseded с причиной и ссылкой.

## Готовность результата

Техническое закрытие в SDD подтверждает поставку. Продуктовая гипотеза закрывается только измерением приёмки, качества, времени и повторного использования. Неудачный эксперимент — допустимый результат discovery, а не повод скрывать данные.
