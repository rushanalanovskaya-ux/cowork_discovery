# Метрики и контракт аналитики

**Предлагаемые определения**, основанные на [SRC-037, слайды 19–20](../evidence/extracted/SRC-037.md) и MVP-27/51. Внедрение и наличие событий не проверены.

| Метрика | Определение | Ограничение |
|---|---|---|
| Weekly accepted delegators | Число уникальных пользователей с ≥1 реальной задачей и явно принятой версией результата за календарную неделю | Исключить тестовые/демо-запуски; timezone фиксируется в отчёте |
| Completion rate | Завершённые с доступным результатом задачи / все допустимые запущенные задачи зрелой когорты | Ошибки и отмены показать отдельно; выполняющиеся не терять |
| Acceptance rate | Принятые без правок + принятые после правок / все задачи завершённой когорты | Нет ответа ≠ отказ; долю неизвестных показывать отдельно |
| Приёмка без полной переделки | Принятые без полной переделки / завершённые задачи | Согласовать различие точечной правки и полной переделки |
| Repeat 14d | Пользователи, повторившие тот же сценарий за 14 дней / пользователи с первым принятым результатом и полным 14-дневным окном | Не включать незрелые когорты |
| Экономия ручного времени | (baseline active minutes − Cowork active minutes) / baseline active minutes | Парные сопоставимые кейсы; включить проверку и исправления; baseline > 0 |
| Время до результата | Время от принятого запуска до готовой версии | Отдельно active time человека и elapsed time |
| Стоимость принятого результата | Согласованные затраты всех запусков когорты / число принятых результатов | Включать неудачные попытки; при нуле приёмок значение не определено |

Пороговые цели ≥70% completion, ≥60% приёмки без полной переделки и ≥30% экономии взяты из питча, слайд 19. Это кандидаты на договорённость пилота, а не доказанный baseline. Для конкретного сценария заранее фиксируются выборка, время наблюдения, правила исключения и пороги качества.

## Минимальные события

`task_started`, `clarification_requested`, `plan_confirmed`, `task_completed`, `task_failed`, `task_cancelled`, `artifact_opened`, `result_accepted`, `result_rejected`.

Общие поля: event_id, timestamp_utc, task_id, attempt_id, scenario_id, product_version, pseudonymous_user_id, tenant_id, is_test. Для приёмки: artifact_version, acceptance_kind (as_is / edited), rework_kind (none / partial / full). Повторная доставка event_id не увеличивает счётчик. Несколько попыток принадлежат одной задаче. Изменение приёмки хранится как событие, а расчёт выбирает последнее состояние версии по определённому порядку.

Не включать содержимое документов и переписок в продуктовые события. Срок хранения, гранулярность доступа и допустимость идентификаторов согласовать с владельцем данных. Аналитика руководителя не предоставляет ему доступ к закрытым пользовательским материалам.
