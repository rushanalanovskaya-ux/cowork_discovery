# Контракт PDLC → SDD

**Предварительный адаптер:** действующий SDD-репозиторий ещё не предоставлен. Этот контракт не утверждает совместимость с его шаблонами. Сначала заполнить `sdd_mapping_ref` ссылкой на согласованное соответствие реальному SDD.

PDLC отвечает за зачем/кому/что/почему сейчас/как измерим. SDD отвечает за проектирование, технические контракты, реализацию и тесты. Не переносить в PDLC полную техническую архитектуру без необходимости.

## Состав пакета

- ID и ревизия, автор/владелец, commit snapshot PDLC.
- Проблема, evidence IDs с источниками, решение и приоритет.
- Scope/non-goals, сценарии и AC-ID.
- Профиль данных, ограничения доступа, UX, зависимости, оценка.
- Эталоны и QA-план, метрики, rollout/rollback.
- Согласования и отсутствие блокеров.
- URL SDD и адаптация к его формату.

Канонические поля — `specs/register.json`; содержание — соответствующий Markdown. Переход к `ready` требует содержательного ревью; скрипт проверяет заполненность, разрешение локальных ссылок и наличие текущего commit без незакоммиченных изменений для экспорта.

```sh
python3 scripts/handoff.py --id PDLC-001 --check
python3 scripts/handoff.py --id PDLC-001
```

Экспорт создаёт versioned ZIP в `handoff/exports/` с постановкой, метаданными и необходимыми ссылочными файлами. Все подтверждающие локальные документы включаются, а внешние ссылки остаются ссылками. Сырые интервью не включаются автоматически. Пакет не отправляется в другой репозиторий. После принятия SDD добавить обратную ссылку, состояние `in_sdd` и дату в журнал решения.

Если меняется требование, увеличить revision и оформить change record. Старый архив не перезаписывается.

## Формат согласования в реестре

Каждое поле в `approvals` после реального ревью содержит объект вида:

```json
{"by": "имя согласовавшего", "date": "2026-09-26", "ref": "decisions/approved-review.md"}
```

Это пример структуры, не согласование. В `ref` допускается существующий файл внутри репозитория или HTTPS-ссылка на реальное ревью. `owner` — фактический ответственный, `blockers` — пустой список только после закрытия вопросов. Поля `decision_ref`, `sdd_mapping_ref`, `estimate_ref`, `qa_plan_ref`, `ux_ref`, `metrics_ref`, `rollout_ref` должны указывать на соответствующие согласованные документы. Внешние ссылки скрипт проверяет синтаксически; доступность и содержимое проверяет ревьюер.

Перед новой ревизией повторно подтвердить затронутые согласования. Машинная проверка не может установить, что человек действительно согласовал документ; подставлять формальные значения ради прохождения запрещено правилами репозитория.
