# Cowork PDLC

База продуктовых знаний и процесс подготовки задач **до SDD** для MWS AI Cowork.

Версия 0.1 · 26 сентября 2026 · рабочий проект на согласование.

**Начните с [START-HERE](START-HERE.md).** Здесь собраны знания, решения, бэклог и постановки, а не только копии discovery-файлов. Репозиторий сохраняет цепочку «источник → наблюдение → проблема → гипотеза → проверка → решение → постановка → SDD → результат».

## Что готово и что требует решения

- Из 39 содержательных файлов создан каталог с контрольными суммами и извлечённым текстом; ключевые выводы связаны с источниками. Полное чтение каждого источника не заявляется: покрытие отражено в каталоге.
- MVP-пункты сохранены с исходными ID, приоритетами, сроками, командой и упоминаниями Jira. Отдельно задан предлагаемый порядок работы.
- Созданы продуктовые постановки и планы экспериментов. Новые критерии приёмки — предложения для ревью, а не утверждённые требования команды.
- **Ни одна постановка пока не имеет статуса Ready for SDD.** Не получены действующий SDD-контракт, оценки и согласования ответственных. Это не мешает анализу и ревью.
- Реализация функций, результаты интервью, оценки трудоёмкости и показатели продукта не выдуманы.

## Работа с репозиторием

Требуется Python 3.8+ и Git; внешние Python-библиотеки для проверок не нужны:

```sh
python3 scripts/check.py
python3 scripts/prioritize.py
python3 scripts/handoff.py --id PDLC-001 --check
```

Последняя команда намеренно возвращает ненулевой код, пока пакет не готов. Для согласованной постановки `python3 scripts/handoff.py --id PDLC-001` создаёт пакет в `handoff/exports/`. Скрипт ничего не отправляет в SDD и не создаёт внешние задачи.

Данные в `backlog/items.json` и `specs/register.json` редактируются в Git; Markdown-карточки содержат продуктовый контекст. Проверка в CI предотвращает потерю связей и неполные Ready-пакеты. Поддерживаются GitHub Actions и GitLab CI.
